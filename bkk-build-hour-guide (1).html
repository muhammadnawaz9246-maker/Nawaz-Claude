1. What the hour produces

Each person leaves with one real output from a task they actually do, spot-checked against its source, red-teamed once, saved as a template, and a two-line note on where things stand. One facilitator can run it for 20 to 25 people in department pods of 3 to 5. Two is easier.

The question to ask at every table, all hour: "Where is it saved, and what did you check it against?"

2. Before the hour: the setup each person needs

  • A folder called Claude with three subfolders: ABOUT ME, OUTPUTS, TEMPLATES.
  • A CLAUDE.md file at the root of that folder (text in the appendix).
  • Three files in ABOUT ME: about-me.md, anti-ai-writing-style.md, my-department.md. The first and third come from a short interview (prompts in the appendix); the second starts from the template in the appendix and gets the team's Urdu and Punjabi rules added.
  • The Claude desktop app, Code tab, opened on that folder. Opus selected.
  • No desktop app or paid plan: a claude.ai Project instead. ABOUT ME text pasted into the project instructions, input files uploaded, outputs downloaded and filed by hand. Same recipe.
  • One task from their own month written as a task map (worksheet page 1), and one input file for it with personal data removed, or the pod's demo seed.

If setup hasn't happened before the hour, spend the first 10 minutes on it and shorten the build. A folder that exists beats a perfect about-me.

3. Data rules

  • No farmer personal data. Names, phone numbers, CNICs, land records: replace with IDs before anything goes in.
  • No salaries, bank details, or unreleased financials unless the manager has cleared the plan in use for that data.
  • Anonymize in 30 seconds: ask Claude to build a fake sample with the same columns, or find-and-replace names with F001, F002.
  • When unsure, use the demo seeds. The system built on a seed works the same on real, cleared data next week.

Bakhabar Kissan holds data on 15 million farmers. A training exercise is the wrong place to test the data policy. Ask IT which plan is in use and what it permits before real data goes in.

4. The recipe, seven steps

  1. Open Claude Code in the folder (or the Project). Confirm it read CLAUDE.md and ABOUT ME.
  2. Paste the task map as the brief. Inputs, steps, output, who it's for, what "right" means. Speak the extra context; the app's microphone or a dictation tool is faster than typing.
  3. Attach one real input, anonymized, or the pod's demo seed.
  4. Ask for the output as .md, .html or .xlsx, saved in OUTPUTS/[the task]/.
  5. Territory check: open the source next to the output. Spot-check 5 rows or 5 facts. Fix what's wrong. Every seed has planted errors, so there is always something to find.
  6. Red-team it once. Pick one of the four prompts in section 7.
  7. Save the shape: "Save this as a template in TEMPLATES/." Then write the resume note: where things stand, and the next step.

The 5-minute timer. Set it at step 2. If someone is still staring at a blank box when it rings, they set another and write their next 5 steps instead of the brief. Three outcomes, all fine: it's done, it wasn't worth doing, or it's bigger than it looked.

What "stuck" looks like

  • Blank box after 3 minutes: speak the brief instead of typing it, or paste the task map line by line.
  • "Run payroll," "content": too big. This month's version of one file for one person.
  • Output looks right, source never opened: open them side by side and use the planted checks in the demo-seeds README.
  • Message 20 of an argument with Claude: ask for a summary, start fresh, paste the summary as message one.
  • A chat answer and no file: "Save that as .md in OUTPUTS/[task]/." Then check the folder and its INDEX.md row.

6. Pod cards: starter prompts and demo seeds

Print one per table. Every card assumes the folder or Project is set up and ABOUT ME exists. Seed files live in demo-seeds/; the README there lists the planted errors. All names and numbers in the seeds are invented.

people & culture · seed: attendance-export.csv

Task: monthly attendance and leave summary.

Read ABOUT ME. Here is this month's attendance export. Produce the monthly summary in this format: headline numbers, then a table by department, then a list of anyone with more than 3 unplanned absences. Flag every row you weren't sure how to classify instead of guessing. Save as .md in OUTPUTS/attendance/.

Territory check: pick 5 employee IDs, count their absences by hand in the CSV.

finance · seeds: bank.csv, ledger.csv

Task: reconcile two exports.

Read ABOUT ME. Reconcile bank.csv against ledger.csv by reference, date and amount, allowing a 1-day date tolerance. Give me an .xlsx with three tabs (matched, bank only, ledger only) and a 5-line note listing each mismatch and what I should check. Don't guess at causes the data doesn't show. Save in OUTPUTS/reconcile/.

Territory check: there are exactly 3 planted mismatches. Did it find all 3 and nothing else?

gis · seed: field-survey.csv

Task: clean a field survey export.

Read ABOUT ME. Here is a field survey CSV. Clean it: standardize coordinates to decimal degrees, dedupe on farm_id keeping the latest visit, flag rows with coordinates outside Punjab, and normalize crop names. Give me the cleaned CSV, the Python you used so I can rerun it next month, and a one-page brief of what changed. Save in OUTPUTS/survey-clean/.

Territory check: 2 duplicates, 1 out-of-bounds point, 3 crop spelling variants were planted.

e-commerce · seed: product-specs.csv

Task: listings and reply templates.

Read ABOUT ME. Here are 8 product spec rows. Write an Urdu and an English listing for each in our house format (title, 2-line benefit, specs, how to use). Use only the specs given. Then write 3 WhatsApp reply templates for the top customer questions: price and delivery, how to apply, is it in stock. Save in OUTPUTS/listings/.

Territory check: compare pack size and price on 3 listings against the CSV.

agri content · seed: agronomist-notes-wheat-sowing.md

Task: advisory in three formats.

Read ABOUT ME. Here are agronomist notes on wheat sowing for Punjab. Turn them into a WhatsApp advisory in simple Urdu (aap register, short lines, every number exactly as in the notes), an English app version, and a 30-second video script. Don't add any number or recommendation that isn't in the notes. Save the three files in OUTPUTS/advisory/ and tell me which lines you were least sure about.

Territory check: seed rate, sowing window, first irrigation timing: identical in all three?

studio · seed: studio-brief.md

Task: brief to production pack.

Read ABOUT ME. Here is the brief for a 90-second farmer testimonial video. Give me a shot list with locations and durations, a 2-day shoot schedule, a script draft in our format with Urdu dialogue and English direction notes, and captions for YouTube, Facebook and TikTok from one master. Save in OUTPUTS/testimonial-video/.

Territory check: does the shot list cover every beat in the brief? Anything invented?

field & conventional · seed: voice-note-transcript.md

Task: visit report from a voice note.

Read ABOUT ME. Here is the transcript of my voice notes from today's 3 farm visits. Turn it into the visit report format (one section per farm: observed, advised, follow-up, owner, date). Pull every follow-up into a single table at the end. Draft the WhatsApp message to each farmer in simple Urdu confirming what we agreed. Save in OUTPUTS/visits/.

Territory check: 4 follow-ups are in the transcript. Are all 4 in the table, with the right farm?

any department · no seed needed

Task: document the process only you know.

Read ABOUT ME. There's a process at work only I know how to do: [name it]. Interview me about it with AskUserQuestion, 8 questions, one at a time, asking for specifics when I'm vague. Then write the SOP: purpose, inputs, numbered steps, common mistakes, how to check it's done right. Save as reference/[name]-sop.md and add a one-line summary to about-me.md.

Territory check: hand the SOP to a pod-mate. Can they follow step 3 without asking you?

7. The red-team card

Paste one of these after any draft, plan or analysis that matters. Ask "why is this bad?", never "is this good?"; a model is trained to agree with you.

1. Disagreement
"Assume this [draft/plan] is a mistake. Give me the 3 strongest reasons a smart, experienced person in my role would not do it."

2. Base rates
"Out of 100 similar attempts at this, how many got the result I want? Name the reference class you're using."

3. Pre-mortem
"It is 3 months later and this failed. Write the post-mortem: what went wrong, in which week, and why."

4. Fermi
"Break this into pieces. Estimate each piece as a range, multiply them, and tell me the number I should expect."

Then the person writes the last line. "I'd ship this as is / with these fixes / not yet, because…" In their words, every time.

8. Show and tell, commit, the first 20 minutes

Show and tell (12 minutes)

  1. Volunteer shows the output and the input side by side. What did Claude get right? What did the territory check catch?
  2. The room picks one red-team prompt. Run it on screen and read the three objections aloud. Ask which one is real.
  3. The volunteer writes the final sentence: "I'd ship this as is / with these fixes / not yet, because…"

Commit (3 minutes, out loud)

  1. One habit, in the "when… I…" form, on the worksheet. For example: "When Claude gives me a number, I ask where it came from."
  2. One task moved into Claude this week, with a day and time on the calendar.
  3. One template saved, or the about-me interview finished, whichever didn't happen yet.

The first 20 minutes back at the desk

  1. 0-5: folder and three subfolders exist, CLAUDE.md saved.
  2. 5-12: finish the about-me and my-department interviews. Speak the answers.
  3. 12-14: edit the anti-ai file. Add the Urdu and Punjabi rules the team actually uses.
  4. 14-16: add one reference file for the most repeated task.
  5. 16-20: run today's task again on this week's real, cleared data. Watch where the output lands and check the INDEX.md row.

Do it with a pod-mate. Two people with the same setup catch each other's gaps.

10. Appendix: the setup prompts and CLAUDE.md

CLAUDE.md, at the root of the Claude folder

This is my Claude folder. You work inside it.

Before any and every task, read these core files in ABOUT ME/:
- about-me: who I am, what I love and hate (plus an index of my reference files)
- anti-ai-writing-style: write, then audit your draft against this file
- my-department: my team's goals and what we're working toward

ABOUT ME/reference/ holds detailed files for repeat tasks. Read one only
when the task matches its summary in about-me. Don't load the rest.

Never read OUTPUTS/ or TEMPLATES/ unless I point you there. When I do, read that folder's INDEX.md first, then open only what the task needs.

Save all deliverables in OUTPUTS/ in a subfolder named after the project. After saving, add or update the file's row in that folder's INDEX.md (file, created, updated, one line on what it is) and set its Last updated date. Create the index if the folder doesn't have one.

Never invent a number, a name, or a source. If the input doesn't contain it, say so and ask.

If the brief is unclear, use AskUserQuestion. Don't fill gaps with filler. Don't over-explain. Deliver the work.

about-me.md: paste into a new Claude Code session, on Opus, and answer out loud

You are building my about-me.md file for my Claude folder. This file will be read by Claude at the start of every session to help you do my job with me. It needs to be concise and high-signal.

Your job: interview me using AskUserQuestion (20 questions), then compile the answers into a condensed about-me.md under 2,000 tokens.

Interview rules: one question at a time. Let me use "Other" to dictate long answers. If I'm vague, push back and ask for a specific example. Follow interesting threads before moving on.

Cover: who I am (role, department at Bakhabar Kissan, who I work with, a good week), how I work (daily tools, how I start a task, how I review, what "done" means), what good looks like, what I hate, my hard rules, the languages I work in and when each one is used, and my contrarian opinions.

Output: a single markdown file. Do NOT save raw Q&A. Extract patterns into condensed prose and bullets. End with a section "Instructions for Claude" holding 10 numbered do/don't rules. Under 2,000 tokens. Save as about-me.md in my ABOUT ME/ folder.

my-department.md: paste after about-me is done, same session

You are building my my-department.md file for my Claude folder. This tells Claude what my team at Bakhabar Kissan is working toward right now so it makes better calls on every task. My about-me.md already covers who I am, so no overlap. Goals and decisions only.

Interview me using AskUserQuestion (6-8 questions), one at a time, then compile a condensed my-department.md under 1,000 tokens.

Cover: my department's top 2-3 goals this year with specific numbers, the crop seasons or business cycles that shape my calendar (Rabi, Kharif, month-end, campaign launches), who reads my work and how they like to receive it, the one metric that means success, and what we're actively saying no to.

Output structure:
# MY DEPARTMENT
## Goals   (bullets, numbers where possible)
## Calendar and cycles   (2-4 bullets)
## Who reads my work   (name, role, format they want)
## Saying no to   (bullets)

Under 1,000 tokens. Save as my-department.md in my ABOUT ME/ folder.

anti-ai-writing-style.md: starter, edit the banned list and the language rules

# MY WRITING RULES

## Voice
- Short paragraphs. 1-2 sentences, 3 max.
- Vary sentence length. No metronome rhythm.
- Contractions always. Use "I" and "you." Active voice.
- Be specific: numbers, names, real examples.
- Take a stance. If you've made the point, stop.

## Languages
- Farmer-facing: simple Urdu, "aap" register, short sentences,
  crop and input names as farmers say them (keep Punjabi terms).
- Internal: English, US spelling.
- Never mix scripts in one message unless I ask.

## Formatting
- Numbers as digits. NO em dashes.
- Bold sparingly. Sentence case headers.

## Banned words (English)
delve, leverage, harness, unlock, seamless, robust,
streamline, elevate, supercharge, game-changer, crucial,
pivotal, tapestry, realm, showcase, foster, empower,
cutting-edge, revolutionize, dive in, in today's world

## Banned patterns (fatal)
- "This isn't X, it's Y." / "Not X. Y."
- "It's not about X, it's about Y."
- Any sentence that negates a framing then corrects it.
Fix: delete everything before the positive claim.

## Also avoid
- Rule of three ("fast, clean, and simple")
- "It's worth noting" / "let's dive in" / "moving forward"
- "I'd be happy to" / "great question"

Turn a solved problem into a skill

Paste at the end of a chat where the steps worked. The skill runs the same way next time.

Read this whole conversation where we worked out [problem]. Pull the repeatable workflow out of it and build a skill: a SKILL.md with a short description of when to use it, the trigger phrases, and the exact steps in order. Keep it generic so it works next time too, not just for this one case. Save it in .claude/skills/ so I can reuse it.
